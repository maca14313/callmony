## What was actually wrong with create/edit contacts

Diagnosed from the code (no repro steps were given):

1. **The pair-order swap (the big one).** `ContactEditorOverlay` /
   `ContactCreatorOverlay` called
   `Platform.contacts.updateContact/createContact(..., valid.map { it.label to it.number }, ..., map { it.label to it.address })`
   while `AndroidPlatform` destructures `for ((number, label) in phones)` /
   `for ((address, label) in emails)`. Result on a real device: a CREATED
   contact's phone number is literally the text "mobile" (TYPE=Other,
   because `phoneTypeOf("0911…")` falls through to TYPE_OTHER) and its
   email address is "home"; an EDIT inserts a new phone row with NUMBER
   "mobile" on every save (the union merge's normalized wanted-set
   contained "" for it, which then inserted). The in-app list looked
   right (it never round-trips through the provider), which is why it
   survived since v1.6.13 — until the 60s TTL refresh re-read the book.
2. **The union merge.** `updateContact` kept every device row the editor
   didn't list ("loss-free union"): deleting a phone row resurrected on
   the next refresh, editing a number doubled it (old kept + new
   inserted), removed emails stayed, and the Company field had NO
   Organization write at all — company edits silently never persisted.
3. **The cache patch** wrote the phone number into `DevicePhone.id`.

## Fixes shipped

- Call sites pass `(number, label)` / `(address, label)`; the interface
  doc now spells the order out. Cache rows get uid()s.
- New pure planner `lib/ContactMerge.kt` (`planPhoneMerge` /
  `planEmailMerge`): matched rows relabel in place, editor-dropped rows
  DELETE, new rows insert. `updateContact` applies it and
  upserts/deletes the Organization row (company persists).
- Known limitation kept (same as always): `+251…` and `0911…` forms do
  not textually match → delete+insert, never a silent duplicate.

## Calculator rework highlights

- Canvas: min 320dp bordered paper box owning the editor body; locked
  ledger + total bar + active line inside; keypad + Aa/123 row pinned.
- Text-default mode: the active line is a BasicTextField on the system
  QWERTY (native selection/clipboard), live-parsed by the same grammar.
- ⌫ fix: trailing operator deletes before the digits to its left.
- `%` (CalcToken.pct, phone-calculator semantics: ± = % of running
  total; ×÷ = /100), `±`, Σ → M+ M− MR.
- Result tag badge → "= total 200" / "= 200 total".
- Next line = small ⏎ key; committed lines lock (long-press copy, ✕).
- Auto-save on existing entries (600ms debounce + on dispose).
- Total bar menu: Make payment (saves first, prefills the payment sheet)
  / Copy total.
- Compact popover (38dp field, 26dp chips, 28dp buttons).
- Keypad digits 20→24sp in the same capped band.
- Just amount / Items / Quick item removed → `removed/2026-10-30-entry-editor-just-amount-items-quick-item.md`;
  calculator is THE amount input; legacy amounts seed the first line.
