## Decoding the report

- `CallmonyApp.kt:296` = the **autolock touch observer**:
  `awaitEachGesture { lastActive = now() }` — runs on EVERY touch anywhere
  in the app (observe-only, added in v1.6.17 for real idle tracking).
- `lastActive` was `remember { mutableStateOf(now()) }` — so every touch
  performed a **Compose snapshot state write**.
- The stack shows that write blocked ~6 s inside `Snapshot.current()` →
  `readable()` — the snapshot system's shared lock/advance machinery.
- Concurrently, `AppStore`'s `Dispatchers.Default` workers wrote snapshot
  state DIRECTLY from background threads: `hydrate()` (16 assignments),
  `doFetchContacts()` (the 1239-contact list publish), `loadSystemCalls()`
  (400-call list), `KeypadIndex` (T9 index), plus `t()` reads and
  permission-callback writes. Cross-thread snapshot writes + a main-thread
  snapshot write per touch = the collision the report caught on a
  low-end Samsung A12.
- The old thread capture (6 deepest × 4 frames) showed only parked workers —
  the actual lock holder was among the unprinted threads, so the exact
  internal mechanism stays probabilistic; the fix removes the entire class
  instead of betting on one theory.

## The fix (v1.6.21, versionCode 31)

1. **Per-touch snapshot write eliminated** — `lastActive` is now a plain
   field on a remembered `TimeRef` class (gesture observer + idle poller
   both run on the main dispatcher; autolock never needs recomposition).
   The exact frozen frame becomes impossible.
2. **Single-writer snapshot rule, app-wide** — no background thread touches
   Compose state (reads or writes) anymore:
   - `hydrate()`: JSON loads on the worker, ALL state assignments in ONE
     `withContext(Dispatchers.Main)` hop (single recomposition); reminder
     rescheduling (t() reads) runs inside the same hop.
   - `loadSystemCallsInner`: decide-what-to-fetch on main → cursor/binder
     on the worker → publish on main (incl. the empty-incremental path and
     the permission callback via `AppStore.publish`).
   - `refreshDeviceContacts`/`doFetchContacts`: address-book cursor on the
     worker; contacts + timestamp publish in one main hop.
   - `KeypadIndex.ensure`: T9 build on Default; `entries = built` published
     on main.
   - Boot bail-out (`AppStore.state.hydrated = true`) hops to main.
   - Boot alarm re-arm: `AppStore.remindersForRearm()` captures the list +
     localized labels on MAIN; the Default hop is binder-only.
   - `MiscOverlays` merge + `RecentsScreen` add-to-contact: binder edits on
     the worker; `pairs` / `addingTo` / toasts / `patchDeviceContact`
     publish on main.
   - `AlarmReceiver` + `NotificationActionReceiver`: read the live flag in
     `onReceive` (main thread), post the live store update to the main
     looper; the worker thread only does JSON surgery + notifications.
3. **Diagnostics upgraded** — freeze captures now dump EVERY thread
   (RUNNABLE/BLOCKED first, 16 frames each, budgeted), and the main
   thread's `Thread.state` is printed — if any freeze ever recurs, the
   report will show the lock holder directly.
