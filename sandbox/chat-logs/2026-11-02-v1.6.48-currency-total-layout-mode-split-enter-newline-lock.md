## The seven fixes

**#1 — THE CURRENCY ACTUALLY CHANGES**: the setting always existed
(Settings → Region + onboarding) but `money()`/`compactMoney()` took
`currency: String = "ETB"` — the calculator, the ledger cards and the
contact balances all printed "Br" whatever the user picked. The default
is now `currency: String? = null` → `AppStore.state.settings.currency`
(one-line fix in Utils.kt, whole-app effect: reading the snapshot state
in composition registers the read, so a change re-renders every amount
the same frame). And the change is reachable from the calculator itself:
a 28dp chip on the canvas header (between the prefix chip and Σ) shows
the live symbol and opens a compact BottomSheet with the eight
CURRENCIES chips ("USD $", "EUR €"…); one tap writes the setting. The
keypad hides under the sheet (wantPad gains `!currencySheet`) and re-arms
on close, exactly like the payments modal.

**#2 — BESIDE, NOT UNDER**: the sum-total column stacked `TOTAL` over the
amount; now one Row — `TOTAL 1,234 Br` (+ items hint, paid · remaining
underneath when paid). New test tag `calcTotalAmount`.

**#3 — THE DATE BESIDE THE INDIVIDUAL TOTAL**: the date moved from the
calculation-text row down to the line's OWN total row (`500 Br · paid
200 · … Oct 31`, spacer-pushed to the row's end); annotation lines with
no total keep their date on the same meta row.

**#4 — THE MODE DECIDES WHAT CALCULATES**: new pure
`applyModeSplit(raw, qwerty)` in Calc.kt — inside one whitespace token,
runs of consecutive same-keyboard characters are separated by one space,
and a QWERTY run that parses as a number is quoted (the v1.6.40 marker).
"555555555dsssssss" with qwerty={9..16} → "555555555 dsssssss" → one
token, total 555555555, `after="dsssssss"`. Single-mode tokens keep
quoteTextNumbers' exact rule (the function folds its behaviour in and
replaces it at all three EntryEdit funnels — the derived calcNote,
commitCalcLine which now reuses the derived parse, and the ± key).
Round-trip stable: the split is plain grammar, so reload → same tokens,
same textModeRanges colours, and an unlock-recommit cycle changes
nothing.

**#5 — ONE SIZE, TIGHTER STACK**: committed line totals F.small(14sp) →
F.body(16sp) = the active line's live "= total" (21sp → 16sp); paddings
6/5/2/10dp → 3/3/1/4dp; the line-total row's vertical padding 2dp → 1dp.

**#6 — THE ENTER KEY, ROUND THREE** (the user explained the why):
v1.6.47's enter COMMITTED the line; the user wanted the native enter — a
newline IN THE SAME individual calculation. `onEnter = { calcKey("\n") }`
appends a real "\n" through the undoable funnel (undoable, no qwerty
mark, never doubling a trailing newline); the grammar splits on \s+ so
"275\n70" reads 345 as ONE calculation; the num field's maxLines 3 → 6
(it was already multi-line); ⌫ over a trailing "\n" removes just the
newline (native backspace contract — the old trimEnd().dropLast(1) would
have eaten a digit). At every parse the newlines FOLD to spaces
(1:1 char-count-preserving replace keeps the qwerty indices aligned) —
so the SAVED grammar stays one-line-per-calculation and, critically, a
pure-annotation active line can never smuggle an embedded "\n" into
CalcNote.text → parseCalcLedger (which would have split it into phantom
lines on reload). Next stays the one commit + save key.

**#7 — THE LOCK ICON, BACK**: v1.6.47 removed the 30dp pill; the user
wants the NOTICE back. A plain `MdiIcon("lock-outline", F.small=14dp,
C.faint)` at the head of every committed line (after the prefix), an
open `lock-off-outline` beside the active line's field — both INERT (no
clickable, the v1.6.47 "weird modals" lesson stands), tags
`calcLineLock:$i` / `calcActiveLock`.

## The latent merge bug the round surfaced

Rewriting the prefix test to ride Next (instead of the no-longer-
committing enter) made it FAIL: `saveEntry`'s update branch copies
exprNote but never copied `calcTitle`/`calcPrefix` — an edit of an
EXISTING entry that only changed the title or the prefix style never
persisted. Hidden until now because drafts were the only writer (the
leave-time create builds a fresh row). Fix: the merge now carries both,
always-wins like exprNote.
