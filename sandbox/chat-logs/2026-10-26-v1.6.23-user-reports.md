## The decode

1. **Not one of the three is a real freeze.** The v1.6.22 spin probe
   earned its keep: every sample shows a healthy main thread (parked at
   nativePollOnce, composing normally, dispatching a touch normally), and
   there are ZERO gesture-loop stacks anywhere — the v1.6.22
   awaitEachGesture fix held.
2. **The common thread: all three "blocked" durations are exactly the
   time the app was NOT in the foreground.** The watchdog pauses posting
   heartbeats while `appForeground=false` — and `onActivityPaused` fires
   for the system permission dialog (Report A, ~5.8 s on the fresh
   install), for switching apps and screen off (Reports B/C, 144 s /
   340 s) — but the BlockageDetector kept its pre-pause baseline. On
   return, `now - lastRanAt` = the away-time → phantom "no progress for
   144822 ms" with an idle main thread. A watchdog false positive.
3. **Report A exposed a REAL second bug**: two workers side by side
   inside `AndroidContacts.fetchAll`. The permission-grant callback's
   `scope.launch { doFetchContacts() }` (Store.kt:263) escapes the
   `contactsRefreshInFlight` single-flight guard — the guard's coroutine
   returns immediately after spawning the fetch, resetting the flag in
   its `finally`. So on a fresh install: grant → callback fetch starts →
   onResume TTL refresh passes the reset guard → second whole-book read
   over 1239 contacts, concurrently, on the same low-end device.

## The fixes (v1.6.23)

1. **Diag.kt — `BlockageDetector.resume()`**: clears the post/run
   baselines; the watchdog calls it on every inactive→active transition
   (DiagAndroid.kt). The paused gap can never read as a freeze; the next
   episode measures from a FRESH heartbeat post; the report cooldown
   survives (no spam). A real stall after resume is still caught — 3 new
   DiagTest cases: `detectorResumeClearsThePausedGap`,
   `detectorResumeMeasuresFromTheFreshPostBeforeAnyRun`,
   `detectorResumeKeepsTheReportCooldown` (12/12 green).
2. **Store.kt — the fetch is the single-flight unit**: `doFetchContacts`
   funnels every caller through a `Mutex` gate (`tryLock` → read →
   `finally unlock`); whoever holds it does the whole-book read, everyone
   else returns instantly. The grant-callback fetch and the onResume
   refresh can never double-read again.
