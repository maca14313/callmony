## Diagnosis + fixes shipped (v1.6.18)

1. FREEZE / LAG / CLOSING ITSELF — root cause: every store mutation ran its whole
   persistence inline on the MAIN thread (full-collection JSON encode + a
   synchronous SharedPreferences commit writing the value TWICE — row + mirror).
   The contact cache re-serialized the entire address book on main-thread contact
   edits; stacked commits crossed Android's 5s input-dispatch limit → ANR →
   "app closes itself". Fix: `lib/Persist.kt` — a single-writer FIFO IO queue; all
   Db saves / cached contacts / cached calls now run on it (main thread never
   touches the disk again). Receivers wrap their load-modify-save in
   `Persist.postAndWait` blocks (ordered with UI writes). The autolock default
   changed from 1 minute (read as "closing itself" while reading) to Never,
   with a "Never" chip added to Settings → Security.
2. REPEAT AT ANY INTERVAL + ALARM — repeat model extended with
   `custom:<n><m|h|d|w|mo>`; the reminder editor gained a Custom chip with a
   number + unit row ("every 90 minutes", "every 2 weeks", "every 6 months"…).
   `nextOccurrence` handles every unit; reminder cards show a human repeat label.
   ALARM reminders (isAlarm) fire on a dedicated channel that rings on the ALARM
   audio stream (USAGE_ALARM, default alarm sound — audible over silent), with
   the alarm icon on cards and a toggle in the editor.
3. TWO SAVE BUTTONS — tapping an entry row now opens the editor DIRECTLY (was
   row-tap → expand → Edit button → editor). The always-open item form confused
   the footer Save with its own button: for existing entries without items it
   starts collapsed behind "＋ Add items", and the item button reads "Save item".
4. ADD PAYMENT — renamed "Record payment" (+ hint line), hoisted to a root-level
   host sheet (it used to be composed INSIDE the scrollable card — unbounded
   height constraints made it pop at the top / float mid-scroll, which read as
   "not working"), and the date became the native calendar picker (was a hand-
   typed YYYY-MM-DD field that produced garbage dates on typos).
5. SINGLE ENTRIES TABS — the section header now carries a ＋ that creates an
   entry of the KIND the active tab shows (Income/Expense on General,
   Credit/Debit on a contact).
6. ATTACHMENTS — lists / notes / reminders can ride on any credit/debit/expense/
   income (entry.refs, LinkRef). Editor: attach chips + "＋ Attach" picker sheet
   (Lists/Notes/Reminders tabs, tap to toggle). Entry detail shows the attached
   entities as tappable chips.
7. SETTLE UP — removed from the ledger chips (AppStore.settleUp kept for API
   compat, unsurfaced).
8. MODALS AT THE TOP — new root-level `HostSheets` slot in the app shell; the
   payment sheets + any nested-in-scrollable sheets render through it, so
   bottom-center placement is guaranteed (see `ui/kit/Kit.kt` HostSheets).
9. BLOCK CONTACTS — More sheet → Block/Unblock (in-app block list that already
   existed in the store model, never surfaced). Blocked contacts show a red
   "Blocked" badge on the detail navbar; calls from keypad/detail/search show
   the blocked notice.
10. SEARCH — the header search entry is a solid brand pill with a white magnify
    (was a ghost-grey icon). The search overlay gained ADVANCED TABS
    (All/Contacts/Entries/Lists/Notes/Reminders/Banks) with live result counts.
11-14. CONTACT DETAIL — "＋ Add to contact" became a More sheet: sideways-
    scrolling labeled social strip (every number's WhatsApp/Telegram + saved
    socials + add), the add-to options, general actions, and Block/Unblock.
    The number picker rows carry the action icon (call/message). The tab body
    sits on its own soft card with hairline + spacing; InfoBlocks are soft
    cards. The navbar number: tap = call (with a brand call icon), long-press
    = copy (as before).
15. SANDBOX BACKUP — worklog.md, this chat log and install_sdk.sh live in
    `sandbox/` inside the repo and are committed every round from now on, so
    nothing is lost if the sandbox or the chat ever disappears.
