Decision: full rollback to v1.6.16, executed exactly as asked. No new fixes,
no diagnostics, no feature work shipped in the app.

## What was done

1. **Working tree restored to the exact v1.6.16 tree** (commit `34076f2`)
   via `git read-tree -u --reset 34076f2` on `main`. Everything after
   v1.6.16 (v1.6.17 PIN/autolock, v1.6.18 features, v1.6.19–23 freeze
   fixes + diagnostics suite) is removed from the tree and preserved in
   git history + GitHub Releases.
2. **The only build change: `versionCode` 26 → 34** (one line in
   `composeApp/build.gradle.kts`; `versionName` stays `1.6.16`).
   Reason: Android refuses to install an APK with a build number lower
   than the installed one (v1.6.23 = 33). The alternatives were shipping
   a non-installable APK or asking the user to uninstall (which deletes
   their data). 34 keeps the "install over, keep data" path.
   Verified proof: `git diff 34076f2 -- composeApp/src composeApp/build.gradle.kts
   iosApp/ settings.gradle.kts build.gradle.kts gradle/` shows exactly that
   one line — nothing else.
3. **Data-safety check (pre-rollback)**: v1.6.16's `Db.kt` JSON loader is
   configured `ignoreUnknownKeys = true`, `coerceInputValues = true`,
   `isLenient = true`, with per-row fallback reads; storage keys and file
   scheme are identical across v1.6.16–v1.6.23. The only fields added
   after v1.6.16 (`Reminder.isAlarm`, `Settings.clock24`) are ignored by
   the old reader → data written by newer versions loads cleanly; no
   uninstall/clear-data needed.
4. **Build + verification**: `assembleRelease` clean (2m 54s).
   `aapt dump badging`: `com.callmony versionCode='34' versionName='1.6.16'`,
   minSdk 23, targetSdk 34. `apksigner verify --print-certs`: signer
   SHA-256 `2f6d65be…869ad` — identical to v1.6.23's APK → installs as a
   direct update with data intact.
5. **Release**: APK at `releases/callmony-1.6.16-rollback-release.apk` +
   `/home/z/my-project/download/callmony-1.6.16-rollback-kmp-release.apk`;
   GitHub Release tag `v1.6.16-rollback`. README Versioning + CHANGELOG
   carry a factual rollback entry. v1.6.17–v1.6.23 releases were NOT
   deleted (user's escape hatch if ever wanted).
