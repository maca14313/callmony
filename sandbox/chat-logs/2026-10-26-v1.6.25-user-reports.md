## Decode + fix map

### 1. THE CRASH — More button / navbar three dots kill the app
**Root cause** (found by reading + Robolectric repro, locked with tests): the
ContactDetail **More sheet** wrapped its content in its own
`Column(Modifier.verticalScroll(...))` — but `BottomSheet` ALREADY scrolls its
content, and a vertically scrollable measured inside another scrollable gets an
INFINITE max-height constraint → `IllegalStateException` at measure time → the
app dies the instant either trigger (`dots-horizontal-circle-outline` quick
action or the navbar `dots-vertical`) sets `moreOpen = true`.
**Fix**: removed the inner `verticalScroll` (ContactDetail.kt); audited every
other `BottomSheet` call site — exactly one had the pattern.
**Regression-locked**: `MoreSheetCrashTest` ×3 (quick action, navbar dots,
block-row render) — all green. (While building the repro I also decoded the
notorious Recents-battery flakiness — see below.)

### 2. "the ledgers dont work properly"
Decoded as the discoverability trio the user spelled out in #5/#6: no visible
edit affordance, no visible per-tab add, chips touching the cards.
- **#5 edit icon**: every credit/debit/income/expense card now carries a
  pencil button (brand-green) beside the amount → opens the editor directly;
  row-tap still edits too.
- **#6 per-tab add + overlap**: the Single-entries header now shows a
  LABELED kind-aware add chip (`＋ Credit` on the Credit tab, `＋ Income` on
  General's income tab, …) plus the plain ＋; the filter strip got its own
  vertical padding so the chips can never sit flush against the cards.
- Ledger primary actions restructured per the redesign spec (below).

### 3. Clicked-input indication — everywhere
The app is bare Compose (no MaterialTheme), so `LocalIndication`'s default
draws NOTHING — no chip, tile, key, card or row ever showed it was tapped.
**Fix**: new multiplatform `PressIndication` (IndicationNodeFactory +
DrawModifierNode — a bounded press veil that springs in on press, fades out on
release) provided app-root through `LocalIndication`; `PressableRow` /
`LongPressText` no longer null their indication. Scrims/toasts stay quiet.

### 4. PIN 4th dot never colored
`submit()` ran synchronously in the same frame the 4th digit landed, so the
unlock/shake recomposition happened before the 4th dot ever painted.
**Fix**: the submit now runs from a `LaunchedEffect` 160 ms after the 4th
digit — the filled dot renders first, the unlock still works.

### 7. Attachments behave like natives
Attached lists/notes/reminders now ride DIRECTLY on the collapsed entry card
(they used to hide inside the expanded detail), and tapping one opens the
entity exactly like its own section does (list → list detail, note → note
editor, reminder → reminder editor) — shared `openRef` helper for both the
collapsed chips and the expanded section. Attaching stays in the entry editor
(＋ Attach → picker with the three tabs).

### 8. Advanced search BEFORE typing
- The type tabs (All / Contacts / Entries / Lists / Notes / Reminders / Banks,
  live counts) are now ALWAYS visible.
- New always-visible refinement row: All kinds / Credit / Debit / Income /
  Expense + Any date / Today / Last 7 days / Last 30 days / Overdue.
- With an empty query, picking any filter enters BROWSE mode — the list shows
  everything of that type, pre-filtered, before a single letter is typed.
- New i18n keys ×5 languages (sr.allKinds / anyDate / last7 / last30 /
  overdueOnly).

### 9. UI redesign — compact, modern, flat, ONLY the existing palette
Per the full spec (no text/number changes, no new hues, flat + subtle borders
over shadows, 4dp/8dp spacing system):
- **Flat**: Card lost its v1.6.24 shadow (hairline only, 16dp corners, 12dp
  inset); primary/danger buttons lost their shadow (the solid fill is the
  affordance); bottom sheets/keypad 10dp → 6dp lift.
- **Contact detail**: compact 48dp navbar band; balance pill directly under
  the header; 6×2 quick-action grid at 7dp tiles / 20dp icons / 2dp gaps;
  6dp-to-hairline / 8dp-to-body; tab-body card 16dp/10dp; InfoBlocks 12dp/8dp.
- **Ledger**: 3 summary cards in one row (12dp corners, 8/7dp inset, Net keeps
  its brandSoft+brand selected-state styling); Credit/Debit/Income (General:
  Income/Expense/Credit) are three equal-width brand-soft buttons in ONE fixed
  row, secondary actions (+ Debit/+ Expense, New group, Share statement) in a
  scroll row beneath; entry cards compact (34dp icon tiles, 15dp amounts, 6dp
  card gaps, 30dp icon buttons).
- Everything from the original screen is preserved — every label (including
  the truncated "Whats…"/"Telegr…" tiles), every amount, every control.

### Bonus: the Recents test battery is green (first time in 5 rounds)
Decoded the notorious flakiness while building the crash repro: the batteries'
`@Before` reset `state.hydrated = false` — but the hydrate `LaunchedEffect`
runs once per composition, so whenever the rule-launch boot finished BEFORE
@Before ran, the reset parked the app on the splash forever → the first
`waitUntil` deadlocked (the exact same 5 ComposeTimeoutExceptions every
round, previously "A/B-proven" as sandbox flakiness). Test-only fix in both
batteries (no hydrated reset; every test already waits for hydrated=true
before seeding). Full suite: **65/65 green**.
