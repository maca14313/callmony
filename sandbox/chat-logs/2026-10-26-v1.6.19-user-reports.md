## Diagnosis (report 1)

- Rebuilt the boot harness (`BootDiagTest`) that runs the REAL app under
  Robolectric with a watchman thread dumping thread stacks. The v1.6.18
  boot NEVER finished `ActivityScenario.launch()`: the main looper was in a
  permanent Choreographer vsync loop with an `InfiniteTransition` running
  frame callbacks back-to-back. (This is what the v1.6.18 round misread as
  "sandbox too slow — killed at 570 s while booting".)
- Bisect: removing the onboarding `BasicTextField` did NOT help; the app
  code contains exactly one `rememberInfiniteTransition` (AlarmDialog pulse,
  not composing). The infinite transition belonged to the Material3
  indeterminate `CircularProgressIndicator` — the Recents "Loading calls…"
  `Spinner(36)` shown while `callLogPerm == UNKNOWN && systemCalls.isEmpty()`
  (a state that persists on every fresh install until the call-log
  permission resolves, and the spinner composed UNDER the opaque onboarding
  sheet from the first frame).
- On a real device this endless frame loop saturates the main thread
  (unthrottled on the reporter's device / low-end silicon) → input dispatch
  starves → the "Callmony isn't responding" ANR dialog → the app closes
  itself. On Robolectric (unpaced frames) it is a hard hang.
- Upgrade-path control experiment (`UpgradeBootDiagTest`: onboarded
  settings, 400 cached calls, repeating/snoozed/done reminders, entries) —
  boots and idles CLEANLY, proving the freeze was the fresh-install
  permission-spinner path, not the v1.6.18 Persist queue.

## Fixes (report 1)

- `AppState.callLogBusy` (true only while a call-log ask/fetch is actually
  in flight; `try/finally` around `loadSystemCalls`).
- The Recents loading spinner renders only when `callLogBusy` &&
  `callLogPerm == UNKNOWN` && `settings.onboarded` (screen actually
  visible). An unresolved permission falls through to the no-calls
  `EmptyState` (no animation at all).
- Boot effect: `ensureChannel()` + `rearmReminders()` now run on
  `Dispatchers.Default` instead of the main thread.

## Fix (report 2)

- `EmptyState` (Kit.kt): was a bare padded `Column` → started at top-left of
  sized containers. Now wrapped in `Box(fillMaxSize().wrapContentSize(Center))`
  → centered in Recents/Reminders/Trash/Notes/Banks/ContactPicker/denied
  card; in scrollables `fillMaxSize` falls back to wrap-content (unbounded
  height) so list empty states keep natural in-flow placement (horizontal
  centering only) — RN behavior in both contexts.
