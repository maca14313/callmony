## The paper calculator (v3) — how it works

- **The token flow** (active line): each `CalcToken` renders as
  `[before-label] NUMBER [after-label] [op]` — plain Text nodes of identical
  metrics (17sp SemiBold; labels C.sub, numbers C.ink, the active number
  brand + underlined), wrapping in one FlowRow, ending with the live
  `= 500 Br` tail (brand ExtraBold). The fold steps survive as ONE muted
  line under the flow ("100 × 2 = 200 Br · 200 + 300 = 500 Br") — show your
  work, paper-style. NO pills, NO per-slot icons.
- **The tag badge**: 14dp rounded box with a 9dp "tag" glyph, offset (-7,-9)dp
  to the number's top-left corner, three visual states (faint / brand-tinted
  when labeled / solid brand while editing). Tapping = popover; the number
  itself = keypad target.
- **The anchored popover**: `DropdownMenu` (material3, styled: C.card, 14dp
  radius, 6dp shadow) anchored at the number — auto-clamped on screen. It
  carries an auto-focused BasicTextField (system QWERTY, placeholder
  "Describe this number (ball, birr…)"), the Before/After Chip toggle, ✕
  cancel and the styled Done (empty submit = delete the label). While it is
  open the numeric keypad HIDES — nothing overlaps the date/method pickers.
- **The stacked ledger**: committed lines (whole token lists preserved) in a
  hairline card, each row = its text + subtotal + ✕, tap = pull back into the
  active row; the running TOTAL bar (committed + active live) finishes it.
  AC clears only the ACTIVE line.
- **The multi-line grammar**: `parseCalcLedger` / `serializeCalcLedger` /
  `calcLedgerTotal` (lib/Calc.kt) — lines joined by "\n", each in the SAME
  free-text grammar (old single-line notes reopen as a one-line ledger; the
  round trip is byte-stable). Save writes committed lines + the active line
  (if any) to exprNote.

## The sum model (v1.6.37)

- `effAmount = base + items + (committed ledger lines + active line)` —
  live on every keystroke, on every tab.
- The amount field holds ONLY the base (typed or derived); items/calculator
  never overwrite it — they ADD.
- The TOTAL row (under the items list, all tabs) shows effAmount with the
  "100 + 200" breakdown; skipped on the calc tab when it would duplicate the
  calculator's own running bar.
- Reopen: `base = savedAmount − items − ledgerTotal` (clamped at 0) — the
  user's typed number survives every edit round trip.
