## What shipped

**#1 — THE COPY BESIDE PAY COPIES ALL THINGS ON THE CANVAS**: the sum-total
row's copy button (and the payments modal's copy, same formatter) now
exports the WHOLE canvas at the moment of the tap — the title, every
committed line with its own total and date, each line's payments, the
ACTIVE line (with its live total — the old export dropped whatever was
still being typed), the items hint, the TOTAL and Paid · Remaining. New
`activeExportNote()` hands the live line to `formatCalcLedgerExport` as the
last line.

**#2 — THE BUTTON IS CALLED SAVE**: the commit+persist button's label reads
"Save" in all five languages (`ee.calcNext` value — Save / መመዝግብ / ኣቐምጥ /
Olkaa'i / حفظ). 100% of the functionality kept: the tap still commits the
active line AND persists the entry through the save pulse; the tag stays
`calcBtnNext` so every harness keeps working.

**#3 — ONLY THE HEADER's CURRENCY IS TAPPABLE**: the little currency glyphs
beside every individual total and the sum total render as PLAIN TEXT now —
no border, no fill, no click (the v1.6.49 scoped picker and its
`currencySheetFor` state are deleted). The ONE tappable currency on the
canvas is the HEADER's chip (`calcCurrencyBtn`), which writes the live
app-wide setting as before. The per-line currency DATA still rides the
grammar untouched (a line's ` ~USD` marker, the entry's `calcCurrency`) so
old rows keep rendering exactly as saved.

**#4 — ONE FONT SIZE, EDITED AND LOCKED ALIKE (the one asked "many
times")**: `CalcFontSizes` collapsed to a SINGLE size — the active field
(Compose text mode AND the native num-mode field), every locked line,
every total, the prefix and the steps all render at it, by construction;
the old model rendered the active line at 18sp while a locked line read
14sp, so the text visibly shrank the moment it committed. AND THE PREFIX
SLOT: always reserved, centered, 14dp — bullet, number or nothing, the
content column starts at exactly the same x in every prefix mode (the
"large gap between the bullet, number, from the content" — the old
left-aligned 16dp column left a wide hole beside a tiny •).

**#5 — THE STEPS IN THEIR OWN CONTAINER, ALIGNED**: the show-your-work
steps ride a soft card-alt box with a hairline (8dp radius), indented by
exactly the prefix column so its left edge lines up with the line text
above it — a distinct calm block instead of loose faint text on the canvas.

**#6 — MANY OPTIONS BY PX**: the Aa chip opens an ELEVEN-STOP pixel ladder
— 12 px → 22 px — one tap each; the choice rides the entry as
`calcFontSize` (a plain number string; the legacy s/m/l markers decode to
13/14/16 so pre-v1.6.50 rows reopen at their own size; out-of-ladder
values clamp in). Pure `calcFontSpOf` + `CALC_FONT_PX_OPTIONS`, pinned by
the harness.

**#7 — THE INSTANT, REPEATING KEYPAD**: Compose's `clickable` fires on
RELEASE — that was the felt lag. New `Modifier.pressKey`: every key fires
the INSTANT the finger lands (DOWN), and the keys that repeat natively do:
⌫ re-fires after 350ms then every 55ms, the space bar after 420ms then
every 90ms, until the finger lifts (the repeat ticker lives in an outer
coroutine scope so a still-held finger — which raises no pointer events —
keeps repeating; a held space types REAL repeated spaces through the new
`␣!` force-append spelling, bypassing the never-double guard exactly like
the native keyboard). The press vibration rides only the initial landing —
a repeating key never buzzes 16×/s. An OnClick SEMANTIC ACTION keeps
TalkBack and the harnesses' performClick on the exact one-press contract.
The timing is pinned pure (`keyRepeatTicks`).

**#8 — THE CALCULATION TYPEFACE (IBM Plex Sans)**: four static weights —
Regular / Medium / SemiBold / Bold — instanced from the official IBM Plex
Sans variable font (SIL OFL, © 2019 IBM Corp.), bundled once as compose
resources (~218KB × 4) and rendered by EVERYTHING that goes with a
calculation: the active line (both input modes — the native num field
loads the Medium cut straight from the APK assets with a guarded
sans-serif-medium fallback), the locked lines, every total, the steps, the
canvas title, the keypad's own glyphs and the ledger card's calculation
preview. Plex was picked for calculation content: open letterforms, tall
unambiguous digits (0/O and 1/l never collide), even rhythm between words
and operators. Every other surface keeps the platform system font.

**#9 — THE UNDERLINE HUGS THE TITLE**: the title row dropped its 30dp
min-height band and 4dp bottom padding (which pushed the hairline ~8dp
under the text) — it now hugs the field's own line box with 2dp of air,
and the field itself renders in the calculation typeface.

**#10 — THE THREE-ZONE ENTRY CARD** ("think like ui or ux designer, why the
content in is a mess"): the old single crammed row — title, four
calculation lines, meta line, status pill, amount, pencil, chevron all
fighting one horizontal band — became three zones, each answering ONE
question: ZONE 1 (who/how much): the pay-percentage ring, the title with
date · payments · due meta under it, and the AMOUNT as the hero number
(17sp, up from 15) at the row's end; ZONE 2 (the math): the calculation
preview in its own soft card-alt container with a hairline and the
calculation typeface, a distinct block instead of loose grey text; ZONE 3
(the state): one tidy foot strip — the status pill left, the running
balance, then pencil + chevron aligned at the right edge. One tap on the
hero row OR the math opens the editor (unchanged); the chevron is still
the only expander; all tags kept.

**#11 — THE "SINGLE ENTRIES" HEADING ROW IS GONE (contact page)**: the row
carrying the "Single entries" title, its ＋ and its collapse chevron (the
"x") no longer renders on a CONTACT's ledger — the entries list directly
under the filter chips, always expanded (a contact has no collapse control
left), and the circular ＋ FAB remains the one way to add. The GENERAL
ledger keeps its heading and controls exactly as before.

**#13 — NO DATA LOSS, PINNED**: the no-data-loss layer (Android Auto
Backup rules + the auto-exported Downloads/Callmony file + the one-tap
restore offer, v1.6.26/34) now has a regression battery proving the
backup round trip never drops a CANVAS field as the canvas grows them:
exprNote (with its ⏎ breaks, @date and ~currency markers), calcTitle,
calcPrefix, calcCurrency, calcFontSize and the payments with their line
attribution all survive export → parse byte-for-byte — and a legacy
backup with no canvas fields at all still loads (the update path is never
a downgrade).
