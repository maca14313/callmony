## The annotated calculator v2 (the chip model)

- **lib/Calc.kt**: `CalcToken` (label-before / number / label-after / trailing op),
  `CalcNote` (token chain + result-label slots around the total), `parseCalcNote`
  (free text → chips — the v1.6.35 grammar incl. glued ops, Arabic digits, the
  '=' cut with result-label extraction), `serializeCalcNote` (chips → the SAME
  free text, byte-stable round trip: "ball 100 × 2 price + 300 transport"),
  `evalCalcTokens` (same precedence/dangling/÷0/implicit-+ semantics), and
  `calcSteps` (the step-by-step folds: ×÷ first, then +− on the running total —
  the user's own example renders as Step 1: 100 × 2 = 200 Br · Step 2:
  200 + 300 = 500 Br). 14-case CalcNoteTest pins it all.
- **The UI (EntryEdit)**: the expression renders as a wrapping FlowRow of
  interlocking chips — [＋ Text] slot · number chip · [＋ Text] slot · operator
  chip — plus a result row `= [＋ Text] TOTAL [＋ Text]`; the AC pill lives in
  the card header; the steps card below shows every fold + the TOTAL. A custom
  4×4 numeric keypad (7-8-9-÷ … .-0-⌫-+) is PINNED above the Save footer and
  drives the chain: digits type into the ACTIVE chip (tap a chip to activate),
  an operator terminates the number, ⌫ edits it (emptied chip = removed with
  its labels), AC clears all. Tapping any [＋ Text] slot or label chip swaps
  the pad for a standard text field on the SYSTEM QWERTY keyboard
  (auto-focused, ✕ cancel, Done submit — empty submit deletes the label);
  submitting returns to the calculation view. Tapping an operator chip cycles
  + → − → × → ÷. Everything recalculates live and re-serializes on save
  (exprNote round-trips; v1.6.35 notes open as chips).
- **Keypad sizing lesson (found via the harness)**: the pinned pad originally
  wrapped plain rows — on a short window the Column measured rows sequentially
  and the LAST rows got crushed to 0–1px (keys unclickable — the diag test
  proved it: `calcKey:+` bounds = Rect(0,0,0,0)). The pad now caps at 206dp
  (4 × ~47dp rows) and FLEXES DOWN via weighted rows in a min/max-heighted
  column, so keys always stay tappable on short screens; the harness uses a
  realistic phone qualifier (w411dp-h891dp-420dpi).
