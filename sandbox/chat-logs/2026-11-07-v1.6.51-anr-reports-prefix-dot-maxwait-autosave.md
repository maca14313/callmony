## Reading the two ANR reports

Both stacks park the MAIN thread inside HardwareRenderer NATIVE calls that
synchronously WAIT ON THE RENDERTHREAD — `nSyncAndDrawFrame` during a
regular draw (report 1, blocked 101 s) and `nSetStopped` during a stopping
window's final draw (report 2, blocked 34.8 s). The render thread itself
was not answering on this Galaxy A12-class device (Android 12, Exynos 850 /
Mali-G52); the main thread had been alive and recomposing right up to the
stall ("Boot phase: ui.compose" is re-marked on every recomposition of the
app root — the marker proves active use, not a stuck boot), then entered a
draw pass and never returned. What the render thread was DOING during those
101 seconds was invisible — the watchdog only ever dumped main's stack.

## What shipped

**THE WATCHDOG CAPTURES THE RENDER SIDE NOW**: an ANR dump carries the live
stacks of the RenderThread and its mali/hwui companions under a
`──── render threads ────` section (max 3 threads × 60 frames), captured
from the watchdog thread at detection time. The next report the user pastes
shows exactly where the stall lives — the v1.6.43 "log the error and
automatically copy it to clipboard" doctrine, extended to the thread that
both reports were actually about.

**THE KILL-PATH DATA PROTECTION**: the moment a blockage is proven (or an
uncaught exception is about to end the process), the whole store is
force-flushed to the Downloads/Callmony auto-backup file SYNCHRONOUSLY from
the watchdog/crash thread — bypassing the 10-minute throttle and the async
Persist queue (a dying process cannot wait for a scheduler turn that may
never come; the main thread is parked, so nothing can mutate the store
under the read; a failed export leaves the previous backup untouched).

**THE ONLY INFINITE ANIMATION IS BOUNDED**: the AlarmDialog's bell pulsed
via `rememberInfiniteTransition` — animating at display rate for as long
as the dialog existed, the one thing that kept the RenderThread drawing
through a 39-minute foreground session on the weakest device class. It now
runs twelve 1.2 s breathe cycles (~14 s, while the user's attention is being
won) and then ends; the dialog stays fully functional with the GPU idle.
The app now contains ZERO infinite animations (every other animation was
already a terminating spring/tween).

**#2 — NO DATA LOSS THROUGH THE KILL PATHS**: the v1.6.26/34 layer (Auto
Backup rules + the auto-exported Downloads file + the one-tap restore
offer) and the v1.6.50 backup round-trip battery are unchanged and
re-verified; the NEW hole the ANR reports exposed is closed twice:
- **THE MAX-WAIT AUTOSAVE**: the old debounce RESTARTED on every keystroke
  — continuous typing never paused 600 ms, so nothing persisted until the
  hands left the keys, and a never-saved DRAFT had no autosave at all. A
  hard process kill (exactly what both field reports show) dropped
  everything typed since the last pause, or the whole draft. The new loop
  writes at most 600 ms behind the canvas — live entry or payable draft
  alike — so any kill can only ever cost the last half-second of typing.
  The dirty key still gates it (an untouched editor writes nothing), the
  `<= 0` validity guard stands, and the leave-time save catches the final
  beat.
- **THE WATCHDOG-TIME FORCE FLUSH** (above): even that half-second window
  leaves a store snapshot on public storage before the system ANR dialog
  finishes drawing.
- Update/reinstall re-verified: private storage survives an in-place
  update by design (MY_PACKAGE_REPLACED re-arms the alarms); Auto Backup +
  the Downloads file + the restore offer cover the reinstall.

**#1 — THE PREFIX SLOT FOLLOWS THE FONT**: the v1.6.50 "always reserved,
centered 14dp" slot could not hold "1." once the pixel ladder climbed —
IBM Plex Sans Bold's digit (≈0.60em) + period (≈0.28em) overtake 14dp from
~15px up, and the prefix Text WRAPPED the period onto its own second row
inside the slot. The width is now COMPUTED (pure
`prefixSlotDpOf(fontPx, lineCount)`): the canvas's own font size × the
advance of the widest number the canvas can show (the digit count of the
last line's number — "10." reserves a wider slot than "9."), floored at
the old 14dp reservation, scaled by the user's fontScale, ONE width per
canvas so the bullet / number / none same-x contract survives untouched —
and the prefix glyphs are single-line no-wrap by construction. The
live-total row and the steps container indent by the same computed column.
